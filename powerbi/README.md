# Power BI build guide

> **Quick start:** open `PowerBI_Workbook.pbip` in Power BI Desktop (Developer Mode / PBIP preview). The semantic model (tables, relationships,
> 57 measures, date/department/stage dimensions) and all six report pages are generated by `python scripts/build_pbip.py` from the CSV
> exports and `measures.dax`. If the data folder is elsewhere on your machine, change the `DataFolder` parameter
> (*Transform data → Manage parameters*). Close the project in Desktop before re-running the script; it overwrites the generated files.
> The manual steps below describe what the script does, so you can rebuild or extend it by hand.

Power BI reads the CSVs that the pipeline exports to [`data/output/powerbi/`](../data/output/powerbi). All row-level logic is already
done in dbt, so the report only aggregates. Power BI Desktop is free (Windows); sharing a live report needs a Power BI account,
so publish screenshots/PDF in the README or use *Publish to web* with the synthetic data.

## 1. Load the data
*Get data → Text/CSV* for each file (or *Folder* and filter), then set these types in Power Query:

| Table | File | Notes |
|---|---|---|
| `pipeline_deals` | `pipeline_deals.csv` | Fact. 4,800 rows. Booleans as True/False; dates as Date |
| `pipeline_stage_stints` | `pipeline_stage_stints.csv` | 12,017 rows. `entered_at`, `exited_at` as Date/Time |
| `sales_team` | `sales_team.csv` | 29 account executives |
| `dim_accounts` | `dim_accounts.csv` | 720 master accounts (latitude/longitude as Decimal; set Data category = Latitude / Longitude) |
| `dept_quarter_summary` | `dept_quarter_summary.csv` | Targets vs bookings vs pipeline by department × quarter |
| `model_scores` | `model_scores.csv` | 724 open deals with ML win probability |
| `model_calibration`, `model_backtest`, `model_feature_importance`, `model_explanations` | `model_*.csv` | ML evidence for page 5 |
| `dq_reconciliation`, `rejected_records` | `dq_reconciliation.csv`, `../quality/rejected_records.csv` | Page 6 |

Then paste the calculated tables and measures from [`measures.dax`](measures.dax) (`DimDate`, `DimDepartment`, `DimStage`, then the measures into a `_Measures` table).
Apply [`theme.json`](theme.json) via *View → Themes → Browse for themes*.

## 2. Relationships (star schema)
```
DimDate[Date]            1 ──► *  pipeline_deals[actual_close_date]    (active: bookings by close date)
DimDate[Date]            1 ··► *  pipeline_deals[created_date]         (inactive; USERELATIONSHIP in measures)
DimDate[Date]            1 ··► *  pipeline_deals[expected_close_date]  (inactive; forecast by expected close)
DimDepartment[department] 1 ──► *  pipeline_deals[department]
DimDepartment[department] 1 ──► *  dept_quarter_summary[department]
pipeline_deals[opportunity_id] 1 ──► * pipeline_stage_stints[opportunity_id]
pipeline_deals[opportunity_id] 1 ──► 1 model_scores[opportunity_id]
sales_team[owner_email]  1 ──► *  pipeline_deals[owner_email]
dim_accounts[master_account_id] 1 ──► * pipeline_deals[master_account_id]   (10 deals have no account: shown as Unknown)
```
Single-direction filters everywhere. `DimStage` is disconnected (drives the funnel / conversion measures).

## 3. Pages (spec)
Every page: a title that states the question, 4–6 KPI cards, 3–4 visuals, slicers for Department / Region / Service line, and a one-line "So what" text box you write.

| # | Page | Visuals and measures |
|---|---|---|
| 1 | **Pipeline Health & Forecast** | Cards: `Open Pipeline EUR`, `Weighted Pipeline EUR`, `Bookings vs Target %` (current quarter), `Pipeline Coverage x` (next quarter), `Win Rate Last 12M`, `Avg Won Deal EUR`. Funnel by stage with `Stage Conversion %`. Stacked column by expected close quarter: `Commit EUR` / `Best Case EUR` / `Pipeline Category EUR` with target line. Monthly bookings vs quarterly target. |
| 2 | **Deal Velocity & Stuck Deals** | Cards: `EUR At Risk`, `Stuck Deals`, `Avg Sales Cycle Days`. Median days in stage vs `stuck_after_days` (clustered column + line). Matrix department × stage with conditional formatting on `Median Days in Stage`. Scatter days in stage vs `amount_eur` coloured by `risk_reasons`. "Fix this week" table: top 15 at-risk deals. |
| 3 | **Manager & Department Performance** | Matrix department → manager → AE: `Bookings YTD EUR`, `Win Rate (count)`, `Open Pipeline EUR`. Bullet-style bar: `Quota Attainment YTD %`. Scatter per manager: open pipeline vs win rate, size = bookings. `Forecast Honesty Gap (pts)` by manager. 100% stacked bar of `loss_reason` by department. |
| 4 | **Europe Market Opportunity** | Filled map by `Open Pipeline EUR` per country; bubble map from `dim_accounts` lat/long. Matrix industry × sales region (colour = `Win Rate (count)`). Pipeline by service line (map cross-filters). Top accounts table with `account_status`. |
| 5 | **Win Probability (ML)** | Line chart from `model_calibration` (`avg_predicted` vs `actual_win_rate`, one line per method, plus a y = x reference). Clustered column from `model_backtest`: forecast vs actual won € per method. Cards: `Model Weighted Pipeline EUR` vs `Weighted Pipeline EUR`. Table of `Review` deals from `model_scores`. Bar of `model_feature_importance`. Add an *Advisory* badge. |
| 6 | **Why this deal?** | Click-a-deal explainer from `model_explanations` and `model_scores`: cards (`Selected Model Win Probability`, `Selected Governed Probability`, `Average Open Deal Probability`, `Selected Deal Amount EUR`), `Reasoning Text`, bar of `Impact (pts)` by `feature_label`, table of `feature_value`. |
| 7 | **Data Trust** | Cards: `Checks Passed` / `Checks Total`, `Rejected Records`. Table of `dq_reconciliation` with PASS/FAIL colouring. Bar of `rejected_records` by `reject_reason`. Bar of `dq_flags` counts (split the column in Power Query). |

## 4. Techniques worth showing in the screenshots
DAX with `CALCULATE`/`USERELATIONSHIP`, a proper date table, inactive relationships, conditional formatting, drill-through from the
department matrix to a deal list, bookmarks for € vs count (field parameter), page navigation buttons, report-page tooltips.
